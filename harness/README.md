# Jake Benchmark Harness

Test suite for evaluating local LLMs as autonomous AI agents. Tests 22 tasks covering email, calendar, task management, security judgment, error handling, and multi-domain coordination.

## Quick Start

### Docker

```bash
# Build
cd harness
docker build -t jake-harness .

# Scan r/LocalLLaMA for new models + QA the dashboard
docker run jake-harness

# Scan only (with persistent dedup state)
docker run -v $(pwd)/state:/harness/state jake-harness scan --summary

# QA the dashboard
docker run jake-harness qa

# Run a benchmark on Pi via SSH
docker run -v ~/.ssh:/root/.ssh:ro jake-harness benchmark qwen3.6:35b high

# Validate a completed run
docker run -v /path/to/runs:/harness/runs jake-harness validate runs/qwen3.6:35b__2026-04-24_180000
```

### Without Docker

```bash
# Scan LocalLLaMA
python3 scripts/scan-localllama.py --summary

# QA dashboard
bash scripts/qa-dashboard.sh

# Validate a run
bash scripts/validate-run.sh /path/to/run-dir
```

## Architecture

```
Pi (Raspberry Pi 5)              Desktop (RTX 3090)
  Jake Gateway (port 18789)        Ollama (port 11434)
  Mock gog CLI                     Model serving
  Benchmark Runner                 Pre-warm + smoke test
       |                                |
       +---- Tailscale (100.x.x.x) ----+
```

### How benchmarks run

1. **Pre-warm**: Desktop verifies model loads at target context window
2. **Config swap**: Update Jake's model/thinking config on Pi
3. **Gateway restart**: Fresh OpenClaw session for each model
4. **Task dispatch**: Send each of 22 tasks via `jake-dispatch.py`
5. **Collection**: Artifacts saved to `results/` and `runs/` (permanent archive)
6. **Grading**: LLM-judged evaluation against task criteria
7. **Publishing**: Dashboard update + GitHub Pages deploy

### Scripts

| Script | Purpose |
|--------|---------|
| `scan-localllama.py` | Scan r/LocalLLaMA for new models/quants to benchmark |
| `qa-dashboard.sh` | Smoke test the published dashboard |
| `validate-run.sh` | Validate a completed benchmark run's artifacts |
| `run-benchmark.sh` | Run all 22 tasks for one model (Pi-local) |

## Hardening (v1)

The harness is hardened around versioned schemas, a runner abstraction,
sanitized failure reports, a docker-friendly CLI, and matrix runs across
ModelSpecs. See [HARDENING-PLAN.md](./HARDENING-PLAN.md) for the full design.

What's in place today:

- `schemas/` — JSON Schema for `task-pack-v1`, `run-artifact-v1`, `failure-report-v1`.
- `tasks-pack-v1.json` — versioned wrapper around the legacy `tasks.json`. Generated by `harness.lib.migrate`; idempotent.
- `lib/` — Python library: `validate`, `migrate`, `sanitize`, `failure_report`, `mock_runner`, `model_spec`, `runner`, `matrix`, `compare`, plus `cli` (`jake-bench`).
- `lib/tests/` — pytest suite with golden fixtures for redaction and isolation contract tests for the OpenClaw adapter.
- CI workflow (`.github/workflows/harness-ci.yml`) runs unit tests, smoke benchmark, redaction audit, and run/matrix/compare integration smoke on every PR touching `harness/`.

Quick commands:

```bash
# Validate
python3 -m harness.lib.cli validate task-pack-v1 harness/tasks-pack-v1.json

# Re-run the migration (idempotent on a v1 pack)
python3 -m harness.lib.cli migrate harness/tasks.json harness/tasks-pack-v1.json

# Smoke benchmark with MockRunner (no GPU, no network)
python3 -m harness.lib.cli smoke harness/tasks-pack-v1.json --out /tmp/jake-smoke

# Run a single ModelSpec via the runner abstraction
python3 -m harness.lib.cli run \
    --pack harness/tasks-pack-v1.json --out /tmp/jb-run \
    --runner mock --spec mock:smoke --thinking off

# Run a matrix of ModelSpecs (Cartesian over checkpoints + options)
python3 -m harness.lib.cli matrix \
    --pack harness/tasks-pack-v1.json --out /tmp/jb-matrix \
    --runner mock --matrix harness/examples/matrix-example.json

# Compare two runs for regressions / improvements
python3 -m harness.lib.cli compare /tmp/jb-run /tmp/jb-matrix/<one-spec-dir> \
    --out /tmp/jb-compare

# Generate a sanitized failure report from a run dir
python3 -m harness.lib.cli report runs/<run-dir> --sanitize public

# Tests
python3 -m pytest harness/lib/tests/ -q
```

### Docker

The same CLI is exposed via the docker `bench` subcommand:

```bash
docker build -t jake-harness ./harness
docker run jake-harness bench validate task-pack-v1 tasks-pack-v1.json
docker run jake-harness bench smoke tasks-pack-v1.json --out /tmp/out
docker run jake-harness bench run --pack tasks-pack-v1.json --runner mock \
    --spec mock:smoke --out /tmp/out
```

For real runs against the Pi gateway, mount `~/.ssh` and pass
`--runner openclaw` plus `--baseline-config <path>` and `--baseline-home <path>`
pointing at a pristine OpenClaw config snapshot. The adapter creates an
isolated `OPENCLAW_HOME` per run via env overlay; it does not mutate
`~/.openclaw/openclaw.json`.
